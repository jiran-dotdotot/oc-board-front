# Codex 적대적 검토

실행할 때마다 이 스킬 기준 [정본 `.claude/commands/adv.md`](../../../.claude/commands/adv.md)를 읽는다.
대상 해석, 제외 파일, untracked 처리, 10개 관점과 팀 배정, 지적 형식, 탈락 기준,
통계, 리포트와 설명 요구는 정본을 따른다. 원문을 복제하거나 수정하지 않는다.
정본을 읽을 수 없으면 그 경로와 사유를 알리고 검토를 시작하지 않는다.

## Codex 실행 방식

- `$ARGUMENTS`는 사용자가 스킬 호출과 함께 지정한 대상이다. 생략 시 정본의 기본값을 쓴다.
  검토 대상이 비었으면 에이전트를 띄우지 않는다. 검토는 읽기 전용이며 수정 요청으로 확대하지 않는다.
- 정본의 `Workflow` JavaScript는 편성과 데이터 흐름을 설명하는 참고다.
  해당 런타임이 없는 Codex에서 그대로 실행하지 말고 `collaboration` 도구로 조율한다.
- 시작 전에 `collaboration.list_agents`와 현재 도구의 동시 실행 제한을 확인한다.
  검토자 10개 관점 → 팀장 3개 검증 → 총괄 1개 역할을 모두 수행하되, 슬롯에 맞춰 여러 차례로 나눈다.
  예를 들어 총 4슬롯이면 조율자 외 최대 3개 하위 작업을 동시에 실행한다.
  `spawn_agent`로 독립 작업을 배정하고 `send_message`·`wait_agent`로 결과를 수집한다.
  완료된 에이전트는 `followup_task`로 다음 역할에 재사용할 수 있으며, 새 역할과 입력을 명시한다.
  재사용 여부와 수행한 14개 역할을 구분해 기록하고, 14개를 동시에 실행했다고 주장하지 않는다.
- 검토자에게는 정본의 담당 관점, 확정한 대상, `location`·`summary`·`failure`·`evidence` 형식만 배정한다.
  각 팀장은 소속 검토자가 모두 완료된 뒤 근거를 직접 검증하고 통계를 남긴다.
  가능하면 자신이 검토자로 작성하지 않은 팀의 보고를 검증하도록 배정한다.
  총괄은 세 팀장의 결과가 모인 뒤 팀 간 중복을 병합한다.
- 구조 조사에서는 프로젝트의 codebase-memory 스킬과 검증 tier를 따른다.
  위임할 때 정확한 프로젝트, 범위, 그래프 세대와 근거·한계를 전달한다.
  그래프 변경은 조율자가 담당하고, 하위 에이전트는 읽기 전용으로 조사한다.
- `collaboration` 자체를 사용할 수 없으면 같은 14개 역할을 순서대로 수행하되,
  독립 에이전트 검증을 수행하지 못했다는 한계를 보고서에 명시한다.

## 전용 도구가 없을 때

- `Skill`: 해당 스킬의 `SKILL.md`를 읽어 적용한다. 설명 단계에서는 사용 가능한 `eli5`를 읽는다.
  `eli5`가 없으면 정본의 대상 수준과 언어로 설명하고 스킬을 실행했다고 표현하지 않는다.
- `AskUserQuestion`: 현재 제공된 질문 도구의 사용 조건을 따른다. 사용할 수 없거나 권한 확인이면
  사용자에게 직접 한 문장으로 묻는다. 필요한 답을 추측하거나 도구를 실행했다고 주장하지 않는다.
- `Artifact`·`artifact-design`: 사용 가능한 발행 도구와 스킬을 확인한다.
  둘 중 필요한 것이 없으면 비개발자용 설명을 로컬 Markdown으로 저장하고 절대경로 링크를 제공한다.
  가능하면 `open_in_codex`로 열어 보여준다. 외부 발행 여부를 명확히 구분하며 별도 서비스 설치를 추정하지 않는다.
- DesignSync 인증이나 레거시 접근이 막히면 정본에 따라 해당 관점의 한계를 기록한다.
  다른 독립 관점의 검토는 계속하며, 접근하지 못한 영역을 검증 완료로 보고하지 않는다.

최종 지적이 0건이면 정본대로 리포트·아티팩트를 만들지 않는다.
그 외에는 정본의 리포트 경로와 최종 보고 범위를 유지한다.
