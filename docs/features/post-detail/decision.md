## 배경

이 화면은 데모 상수(`detailData.ts`)로만 그려져 있었다. react-query 호출 0건, `useParams` 없음,
`postId` 를 한 번도 읽지 않았고, `목록` 은 `boardId: 'notice'` 하드코딩이었다. 이전/다음·링크복사·
인쇄·수정·첨부다운로드·공감칩·답글은 `onClick` 이 없는 죽은 버튼이었다.

## 구현 중 실측으로 잡은 결함 3건

1. **조회수 이중 집계** — mutation 마다 상세를 `invalidateQueries` 하니 재조회가 일어나고,
   `GET /post/{post}` 는 호출마다 `view_logs` 를 1건 넣었다(당시 연동 실측). 실측: 공감 한 번에 28 → 29.
   → 상세는 **invalidate 하지 않고 캐시를 직접 패치**한다(`utils/postCache.ts`).
   `staleTime: Infinity` + `refetchOnMount/Focus/Reconnect: false`.
   새 Go의 ACT 상세도 호출마다 동기적으로 열람 이벤트를 추가하므로 이 캐시 결정은 유지한다
   (`docs/api/go/05-post-read.md:42`·`:474`). 새 경로는 `GET S/posts/{id}`다.
2. **초점 유실** — 진행 중 `disabled={busy}` 를 걸면 초점을 쥔 칩이 비활성되어 브라우저가 초점을
   `body` 로 되돌린다. 실측: 키보드로 공감 토글 후 초점이 사라졌다.
   → 컨트롤을 끄지 않고 `aria-busy` 로만 알리고, 중복 요청 가드는 호출부에 둔다.
3. **삭제된 부모의 자식 답글 유실** — 자리표시자를 early return 으로 그리면 살아 있는 답글까지
   사라진다. 자식은 연쇄 삭제되지 않는다(새 원문 `docs/api/go/07-post-comment-like.md:41`, `docs/api/go/05-post-read.md:239`). 레거시도 자식을 유지한다(`Comment.vue:333`).
   → 자리표시자 뒤에 자식을 계속 렌더. 같은 원인의 두 번째 버그가 `mapCommentTree` 에도 있었다
   (정규화가 `fn` 결과를 원본 자식으로 덮어써 새 답글이 버려졌다) — 단위 테스트가 잡았다.

## 검증 환경 함정

**happy-dom 에서 DOMPurify 가 조용히 실패한다.** `isSupported: true` 를 보고하면서
`'<p>a</p><script>x</script>'` → `'a<script>x</script>'` 를 돌려준다(script 가 살아남는다).
보안 경로를 그 환경에서 검증하면 «통과»가 거짓이 되므로 살균 검증은
`tests/e2e/post-sanitize.spec.ts`(실브라우저 Playwright)로 옮겼다. 실브라우저에서는 정상이다.

  운영 S3/CDN·브라우저 접근은 별도로 확인한다.

### M-9 추가 반영 (사용자 결정: 「댓글에도 「+」 팝오버 추가」)

정본 댓글 행엔 하트 하나뿐이지만 서버·레거시는 댓글에도 자유 이모지를 허용한다.
게시글 공감의 고정 세트 팝오버를 **사본을 만들지 않고** 공용 `ReactionPicker` 로 빼서
게시글·댓글이 같은 것을 쓴다.

- 댓글 미허용 글에서는 트리거를 **렌더하지 않는다** — `disabled` 만 두면 이유가 보이지 않는다.
- 댓글용 `size="sm"` 트리거는 아이콘이 12px 이라 그대로 두면 터치 대상이 12×12 였다.
  음수 마진 + 패딩으로 **레이아웃을 밀지 않고** 히트 영역만 24×24 로 넓혔다
  (WCAG 2.5.8). 실측: 트리거 24×24, 액션 줄 높이 20px 유지, 가로 스크롤 없음.
- 정본 편차로 기록한다: **정본에 없는 컨트롤을 댓글 행에 추가**했다(사용자 결정).

### 2회차 `/adv` 잔존 결함 처리

2회차는 **부분 실패**했다(팀장A·팀장B·총괄이 세션 한도로 죽어 동작·계약·죽은코드·정본·색·접근성
**7개 관점 결과가 유실**). 살아남은 팀C 몫만 처리했다.

| 심각도 | 조치                                                                                                                                                                                                                                                                                                                                                       |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 높음   | `PostComments.tsx` Escape 에 `isComposing` 가드 — IME 조합 중 ESC 가 작성 중인 본문을 버렸다. 실브라우저 재현 검증: 조합 중 ESC 는 「한참 쓴 긴 답글입니다」 보존 + 창 유지, 조합 후 ESC 는 정상 닫힘 + 초점 복귀                                                                                                                                          |
| 중간   | `postHtml.ts` 의 `position` 무차별 제거를 걷어내고 **`.post-body { contain: paint }`** 로 대체. 실측: 덮개 `position:fixed` 1429×729 → **300×100 으로 갇히고**, 작성자의 `absolute` 캡션은 지정 위치(left 20) 유지. `;` split 로 `url('a;b.png')` 를 깨뜨리던 문제도 함께 사라짐. e2e 단정을 「position 제거」에서 「박스 밖으로 못 나감」으로 다시 세웠다 |
| 중간   | 인쇄 팔레트에서 **임의 hex 14개 삭제**. `:root` 를 넣어 라이트 인쇄까지 오염시키던 것을 없애고, `.dark` 블록을 **`@media not print`** 로 감싸 인쇄에서는 라이트 «정본값»이 그대로 쓰이게 했다. 실측: 라이트 인쇄 표 테두리가 `#cccccc` → 정본 **`#e5e7eb`** 로 복구, 다크 인쇄는 `#000`/`#fff`                                                             |
| 낮음   | en 복수형 `1 times`·`1 reactions` → 저장소 관용 **「(s)」** · 내역 모달 `queryKey` 에서 언어 제거(요청에 `lang` 을 안 보내는데 키에만 있어 전량 재요청)                                                                                                                                                                                                    |

사용자 UI 결정은 보존했고 이 문서 갱신이 현재 화면의 Go 전환 완료를 뜻하지 않는다.
서버 응답에 없는 필드·기본값을 과거 백엔드 문서에서 가져와 만들지 않는다.

⚠️ 가정: 고정 세트의 4번째를 `🎉` 로 두었다. 스크린샷의 4번째 글리프가 이미지에서 확정되지 않아
기존 `REACTION_EMOJIS` 순서를 따랐다. `REACTION_PINNED` 상수 한 줄이라 교체가 쉽다.
