## 1. BR-032 · `is_not_paging`이 문서는 배열, 실행 서버는 페이지 봉투

**증상(실측)** — 같은 토큰으로 직접 호출한 결과:

- `GET {S}/posts?is_not_paging=1&limit=5&badges[]=NOTICE` → **200**, 최상위 키 `["$schema","data","current_page","last_page","per_page","total"]`
- `GET {S}/drive-files?is_not_paging=1&limit=5` → 동일. `is_not_paging=true`로 보내도 동일(엄격 bool 파싱은 통과, 400 아님)

즉 `Array.isArray(body) === false`. 배열을 기대한 화면이 `.map`/`.slice`에서 TypeError로 통째로 죽었다
(홈 「최근 자료」, 게시판 목록 전체). **200이라 네트워크 탭만 봐서는 드러나지 않는다.**

**문서 쪽 기재** — `go/05-post-read.md:39`·`:307`, `go/09-drive-file.md:108`·`:215` 네 곳이 모두 "배열 반환"이라고 적혀 있다.

**필요한 회신** — 신규 API는 필요 없다. 둘 중 어느 쪽이 계약인가:

1. **배열이 의도** → 실행 서버의 봉투 반환이 회귀다(서버 수정 대상)
2. **봉투가 의도** → 위 네 문서 지점이 stale이다(문서 수정 대상)

**프론트 현재 조치** — `is_not_paging`을 더 이상 보내지 않고 `take`/`page` 페이지 봉투 한 가지로 통일했다.
봉투·배열을 모두 삼키는 관용 파서는 두지 않았다(다음 회귀를 조용히 숨기므로). 확정되면 그때 맞춘다.

## 2. BR-012 · 독립 로그인(ID/PW)에서 member 계약 API를 쓸 방법이 없음

**증상(실측)** — Go 로그인으로 받은 **board 토큰**으로 member 경로 4개를 호출한 결과 **전부 401 `UNAUTHORIZED`("Authentication required.")**:

- `PATCH /companies/{c}/settings/users/me`
- `PATCH /companies/{c}/settings`
- `PUT /companies/{c}/settings/users/me/recent-search-keywords`
- `GET /companies/{c}/departments`

**계약 쪽 기재** — `go/01-auth-user.md:318`은 상위 토큰을 클라이언트에 반환하지 않는다고 명시하고,
`go/README.md:72`·`:73`의 HS256 board와 ES256 member는 교환 불가다.
**독립 ID/PW 경로에서 member 자격을 얻는 계약이 Go 문서 집합에 없다.**

**필요한 회신** — 둘 중 하나로 확정해 달라(요청안, 현행 아님):

1. 안전한 member 자격 획득·갱신 흐름을 문서화 — 토큰 종류·응답 필드 타입·갱신/만료 계약 포함
2. 또는 동등한 사용자·회사 관리자 권한 검사를 유지한 **board 인증 설정 엔드포인트** 제공

검증 완화나 board 토큰의 무조건 수용을 요청하는 것이 아니다.
상위 SSO가 별도 member 토큰을 주는 배포라면 그 **전달 계약**만 알려 주면 프론트에서 토큰을 분리해 해결된다.

**프론트 현재 조치** — 개인·회사 설정 mutation을 삭제하고 항상 거절 처리했다.
설정 화면의 알림 스위치 4개와 저장 버튼은 **비활성 + 사유 문구**로 표시한다(조용히 실패시키지 않는다).
게시판별 본인 알림은 board 계약 `PUT {S}/boards/{id}/my-notification`으로 전환해 200 확인 — 이 결손 범위에서 제외.

## 3. BR-029 · 다운로드 presign 미가동 + 브라우저 S3/CDN 접근 환경 확인

**증상(실측)** — 코드 전환은 끝났고 `…/drive-files/{id}/download-url`·`…/attachments/{id}/download-url`을 호출한다.
로컬 실행 서버는 이 두 경로에 **503 `SERVICE_UNAVAILABLE`** 를 반환한다.
`go/09-drive-file.md:25`의 "다운로드 presigner 미설정" 503 항목과 일치하므로 **프론트 결함이 아니라 환경의 서명자 미설정**이다.
**다운로드 200 경로는 이번에 성공 사례를 확인하지 못했다.**

**필요한 회신** (배포 담당자):

- 각 환경에서 presigner가 설정되어 있는가 / 언제 켜지는가
- 실제 프론트 Origin에 대한 **presigned PUT/GET** 동작, 필수 요청 헤더, 버킷 IAM·CORS, CDN 원본 접근
- 승인된 테스트 파일로 브라우저 경로를 검증한 결과 + 환경/버전

⚠️ 실서명 URL·비밀키는 회신에 넣지 말 것(대장에 저장하지 않는다).
API 계약 변경이나 임의 S3 URL 조립 우회는 요청하지 않는다.

**프론트 현재 조치** — 503을 「지금은 내려받을 수 없습니다」 안내로 정직하게 표시하고 우회하지 않는다.

## 4. BR-011 · 관리자가 남의 글을 삭제할 수 있어야 하는가 (제품 정책)

**상황** — 프론트 게시글 상세는 `is_mine || is_admin`이면 삭제 메뉴를 보여 준다.
Go 계약(`go/06-post-write.md:340`)은 **같은 회사 작성자·미삭제**만 삭제를 허용하므로,
관리자가 타인 글을 지우면 **`200 {affected:0, ignored_ids:[id]}`** 로 조용히 거부된다.
`go/05-post-read.md:209`의 상세 `is_admin`은 회사·카테고리·게시판 관리자의 OR이지만 삭제 허가는 아니다.

※ Laravel 시절 단건 삭제는 작성자 또는 회사 관리자 또는 게시판 관리자를 허용했다(`laravel/06-post-write.md:204`).
정책이 의도적으로 바뀐 것인지 확인이 필요하다.

**필요한 회신** — 관리자의 타인 글 삭제를 **제품 기능으로 유지하는가?**

- **유지한다면**: 같은 회사·관리 대상 게시판 범위 안에서 회사/게시판 관리자 허용 여부를 계약에 명시하고, **복원 주체**까지 계약화해 달라. 카테고리 관리자는 별도 정책 판단이 필요하다.
- **작성자 전용이라면**: 그 결정에 따라 프론트에서 관리자 삭제 메뉴를 제한하는 후속 작업으로 처리한다.

새 응답 필드는 요청하지 않는다(`affected`/`ignored_ids`는 이미 있다).

**프론트 현재 조치(2026-09-09)** — 이 문서의 이전 판은 「프론트가 `affected` 를 검사한다」고 적었으나 사실이 아니었다.
그때는 `deletePost` 가 판정값을 계산만 하고 아무도 읽지 않아, 전건 거부(200 `affected:0`)에도 목록으로 이탈했다.
지금은 [usePostDetail.ts](../../src/hooks/usePostDetail.ts) 의 `removePost` 가 `affected === 0` 을 오류로 올리고,
화면은 「작성자만 이 글을 삭제할 수 있습니다」를 띄우며 상세에 머무른다. **삭제 메뉴의 노출 여부는 위 회신에 따라 정한다.**

## 5. BR-028 · 배포값 확인 (공개 API origin·인증 구성·토큰 TTL)

**상황** — 코드 기본값만으로는 실제 값을 확정할 수 없다.
문서의 localhost 예시나 기본 TTL을 운영값으로 고정하면 연결·세션·저장 오류가 생긴다.
(운영 장애를 확인한 항목은 아니다.)

**필요한 회신** (배포 담당자) — 환경별로:

- 공개 API origin
- 활성 board/member 인증 구성
- access/refresh **실효** TTL
- 상위 프록시의 요청 크기 한도

⚠️ 비밀키·실토큰은 전달하지 말 것. 비민감 값과 환경/버전/확인일만 계약 배포 기록으로 남긴다.
확인 전까지 프론트는 현재 localhost 예시를 제품 배포 설정으로 채택하지 않는다.
