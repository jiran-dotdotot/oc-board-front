**그럼에도 남긴다.** 근거:

## 2. 「최근 자료」 행에 북마크 버튼을 남긴다

**정본에는 없다.** `aria-label="자료 북마크"` 는 `isDrive` 블록에만 있고, 정본 최근 자료의 행 액션은

## 3. 업로드를 전체화면 모달로 만든다

**정본에는 업로드 모달이 없다.** 정본은 표 행 안에서 진행률만 보여 준다
(`f.showBar` / `f.pctLabel` / `f.isDone`). 다만 정본 주석이 「업로드 = 가짜 업로드 데모」라고
스스로 밝히고 있어, **정본이 업로드 흐름을 설계하지 않았다**고 읽는다.

**모달로 간다.** 레거시 `UploadDataModal.vue`(900px) 와 같은 구조다. 모달이 주는 것:
등록 «전에» 목록에서 파일을 빼는 스테이징, 드래그앤드롭 영역, 파일별 실패 사유, 재등록(성공분 제외).
이건 정본의 인라인 진행률로는 담을 수 없다.

**따라오는 결과**: 모달이 스크림으로 표를 덮으므로 «목록 행 안의 진행률»은 만들지 않았다.
승인된 플랜에 「모달의 행 + 목록 행 둘 다」로 적어 두었던 것은 모순이었다.

## 4. 저장 용량 게이지 임계 90%

`usagePct >= 90` 이면 막대가 `bg-destructive` 로 바뀐다. **이 임계값은 API 계약이 아니라 아래 Vue 동작과 사용자 결정에 근거한다.**

**레거시 근거로 유지한다.** `../jupiter-board-web/src/pages/drive/[driveId]/index.vue:293-309`
가 사용량 ≥90% 에서 막대를 빨강으로 바꾼다. 용량이 차 가는 것을 업로드가 실패하기 전에 알리는 실익이 있다.
값을 바꿀 때는 이 문서와 레거시를 함께 고친다.

## 5. 미리보기는 이미지·동영상·PDF 만 (한글·오피스 회귀)

`src/components/drive/preview.ts` 의 `previewKind()` 는 이미지·동영상·PDF 만 열고 나머지는

**레거시 대비 회귀다.** `DrivePreviewModal.vue` 는 HWP(자체 뷰어)·오피스(Google gview iframe)·
HEIC(변환 후 표시)까지 창 안에서 열어 준다. 한국어 사내 게시판에서 HWP 는 주력 포맷이라 체감이 크다.

**의도된 단계적 축소다.** 사용자 지시: 「미리보기는 가능하게만 만들어 나중에 대대적으로 공사를 할거야 —
이미지·영상·PDF·한글 이렇게 되도록」. 확장 지점은 `previewKind()` 한 곳이며, 형식만 추가하면 붙는다.

**남은 작업**: HWP 뷰어 · 오피스 뷰어 · PDF 전용 뷰어(페이지 이동·확대) · 기존 저장분 HEIC 표시.

## 6. 폴더 항목 수 `N개` 를 표시하지 않는다

정본 폴더 행은 이름 옆에 `{{ fo.n }}개` 를 보여 준다. **표시하지 않는다** — Go `FolderView`의
필드 목록에는 파일 수가 없다([FolderView·FolderNode](../api/go/08-drive-folder.md#folderview)). `child_drive_folders`로
«하위 폴더» 수는 셀 수 있지만 그것을 「N개」로 쓰면 오해를 부른다.
파일 수 표시를 재개하려면 Go 목록 계약으로 조회 가능한지 먼저 확인하고, 계약이 부족하면 대장에 요청한다.
사용자 판단: 생략 유지.

## 12. 미리보기 관련 지적은 제외 (사용자 결정)

3회차 검토의 다음 항목은 **미리보기 «기능»을 아직 만들지 않기로 한 결정**에 따라 제외한다.

| 지적 | 내용 | 처리 |
|---|---|---|
| M8 | 라이트박스 버튼 배치가 정본과 다르고 `N / M` 인덱스가 없다 | 제외 — 미리보기 기능 확장 시 함께 |
| H5 중 일부 | HWP·오피스 미리보기 | 제외 — §5 의 단계적 축소 결정 |

단, **H5 중 「`<video>`·`<iframe>` 이 공용 Modal 의 포커스 대상 목록에 없다」는 고쳤다.**
그것은 미리보기 «기능»이 아니라 **공용 `Modal` 의 결함**이고(어떤 모달이든 미디어·iframe 을 담으면
같은 문제가 난다), 2회차의 「라이트박스를 공용 Modal 로 이관」이 만든 회귀다.
`FOCUSABLE` 에 `iframe, video[controls], audio[controls]` 를 추가했다.

### 자기 수정이 만든 회귀 (전부 수정)

| 회귀 | 원인 | 수정 |

| 진행 모달이 스크림 두 겹 아래로 가려짐 | 라이트박스와 진행 모달이 동시 마운트 | 미리보기에서 다운로드 시 **미리보기를 먼저 닫아 겹침을 제거** |

| 미디어 컨트롤·PDF 본문에 초점 불가 | `FOCUSABLE` 에 `iframe`/`video` 누락 | 선택자 보강 |
| 삭제 확인이 폴더에도 「휴지통·복구 가능」을 약속 | 3차에 문구를 바꾸며 파일/폴더를 구분하지 않았고 개수 보간도 지웠다 | 파일/혼합 2분기 + 개수 보간 복원 |

### 문구 정정 — 폴더 삭제의 «영구 소멸» 범위

당시 리포트 정정은 과거 백엔드 단건·다건 삭제의 차이를 설명한 기록이었다.
현재 구현 근거는 Go `DELETE S/folders` 하나다(`docs/api/go/08-drive-folder.md:206`·`:238`).
Go는 폴더를 soft delete하고 하위 `FAIL` 파일·관련 북마크를 함께 처리하며, 과거의
hard delete나 `drive_folder_id=null` 고아 처리를 구현 계약으로 가져오지 않는다(`docs/api/go/08-drive-folder.md:242`).
Go 폴더 엔드포인트 5개의 목록에도 복원 계약은 없으므로 폴더를 복구 가능하다고 안내할 근거가 없다
(`docs/api/go/08-drive-folder.md:104`·`:313`, 전체 경로는 [Go 카탈로그](../guides/api-catalog.md)).
기존 사용자 결정과 UI 문구 수정은 유지하며, 복원 기능이 필요해지면 요청 대장에 올린다.

### M11 — 상태 배경 위 전경색 토큰이 정본에 없다

`text-destructive` on `bg-destructive-bg` 는 라이트 2.82:1 · 다크 3.76:1 로 13px 본문 4.5:1 미달.
정본 토큰표에 «`*-bg` 위 전경색» 쌍이 정의돼 있지 않다(`l-*` 파스텔용 `--color-on-pastel` 만 있고,
그것은 테마 무관 고정이라 다크 틴트 배경에서 쓸 수 없다).

**토큰을 발명하지 않고** 색을 유일한 신호로 쓰지 않는 방향으로 해결했다 —
좌측 띠(`border-destructive`) + 아이콘이 «형태» 신호를 담당하고, 글자는 고대비 본문색(`text-gray-900`).
실측: 라이트 **15.0:1** · 다크 **11.72:1**.

**남은 과제**: 정본표에 `*-bg` 세트의 전경색 쌍을 정의하면 이 화면의 처리를 그 토큰으로 교체할 수 있다.

**교훈 1 — 치환 결과를 확인하지 않으면 「고쳤다」가 거짓이 된다.**
2회차에 3건(`pending` 필터·라이브 영역 2건)을 「수정 완료」로 보고했으나 코드에 들어가지 않았다.
prettier 재포맷으로 문자열 치환이 실패했고 성공 메시지만 출력됐다. 이후 모든 치환에 `assert` 를 걸고
작업 후 grep 으로 전수 확인한다.

**교훈 2 — 접근성 장치는 «다른 장치와 겹칠 때»를 함께 설계해야 한다.**
포커스 트랩·초점 복귀·라이브 영역은 각각 단독으로는 맞았지만, 모달이 겹치거나 패널 내용이
런타임에 사라지는 순간 서로를 방해했다. 2·3회차 높음의 대부분이 이 유형이다.
