# 003. 백엔드 Go 전환에 따른 API 문서 이원화

2026-09-08 · 확정

> **현행 출처는 맨 아래 「추가 결정: 새 Go 원문 전면 교체」와 [API 문서 안내](../api/README.md)다.**
> Go 전용 구현·역방향 갭 보고 정책은 유지한다. 아래 초기 배치 기록은
> 당시 결정 이력으로 보존한다. 스냅샷 보관 결정은 유지하지만, 당시의 읽기 순서·카탈로그 구조·
> 자동 삭제 시점은 새 정책의 지시로 해석하지 않는다.

## 배경

백엔드가 Laravel(`jupiter-board-api`, 72 엔드포인트) → Go(`oc-api-go`, 67)로 재작성됐다.
프론트는 아직 Laravel 계약 위에서 동작한다(`src/services/**`, `src/types/**` 전부 Laravel 기준).
두 계약이 상당히 다르다 — 경로 스코프(`{company_id}/{user_id}`), 인증(Passport → 자체 board 토큰),
에러 봉투, 페이지 봉투 5키, 불리언 파싱 4종.

## 결정

**Go 를 정본으로 삼고 Laravel 을 함께 보관한다.** 삭제하지 않는다.

```
docs/api/
  README.md      ← 어느 걸 볼지 · 재복사 명령 · 프론트가 당장 알아야 할 차이
  go/            ← ✅ 정본 (11파일: README + 01~10)
  laravel/       ← 참고 (11파일: 00-overview + 01~10)
```

- 새 구현·타입·서비스는 **Go 계약**을 따른다.
- Laravel 판은 **기존 구현이 무엇 위에 서 있는지 확인**하고 마이그레이션 차이를 추적하는 데 쓴다.
- 색인(`docs/guides/api-catalog.md`)은 **재작성하지 않고** 기존 Laravel 표에 `Go 경로` 열을 더했다.
  Go 에 대응이 없는 5개는 `✖ 없음`(72 − 67).

## 왜 Go 가 정본인가

운영 대상이 Go 로 바뀌었으니 계약도 Go 다. 그 외에 문서 자체의 신뢰도도 높다 —
Go 판은 라우터 골든 파일(`testdata/routes.txt`, `TestRouteTable` 이 실 gin 라우터와 대조)로
**문서 개수와 등록 개수가 일치함을 코드로 확인**했다고 밝히고, 규칙마다 근거 파일:라인을 단다.

## 왜 Laravel 을 남기는가

1. **현재 코드가 그 위에 있다.** 서비스·타입·훅이 전부 Laravel 필드명과 경로를 쓴다.
   교체 중에는 「원래 무엇이었나」를 봐야 한다.
2. **과거 결정 문서가 참조한다.** `002-drive-canon-deviations.md` 등은 Laravel 문서의
   특정 줄을 근거로 삼는다. 파일이 사라지면 그 근거를 검증할 수 없다.
3. **차이 자체가 정보다.** Go README 의 대조표가 「Laravel 은 이랬다」를 전제로 쓰였다.

## 정리(삭제) 시점

`src/services/**`·`src/types/**` 가 **전부 Go 계약으로 옮겨지고** DoD 가 그린인 시점.
그때 `docs/api/laravel/` 을 지우고 이 ADR 에 「정리 완료」를 덧붙인다.
그전에는 지우지 않는다 — 마이그레이션 중 「원래 어땠나」를 못 보게 된다.

## 스냅샷 규칙

두 판 모두 백엔드 저장소의 복사본이다. **본문 직접 수정 금지**, 갱신은 재복사.
여기서 손대면 다음 복사 때 조용히 사라지고, 그 사이 우리 수정본을 계약으로 믿게 된다.
Go 판 `README.md` 는 rename 하지 않는다(재복사 때마다 손봐야 하므로).
파일명 대응은 `docs/api/README.md` 에 적었다 — Laravel `00-overview.md` ↔ Go `README.md`,
Laravel `10-drive-upload-department-live.md` ↔ Go `10-upload-department-client.md`.

## 함께 고친 참조

`CLAUDE.md`(API type policy·화면 작업 순서·소스 역할표·가정 원장) ·
`docs/guides/api-catalog.md`(헤더·도메인 링크·§0 를 Go/Laravel 로 이원화) ·
`docs/guides/api-reference.md`(Laravel 기준으로 쓰였다는 경고 추가) ·
과거 결정 문서 2건의 인용 경로를 `docs/api/laravel/` 로 고정.

## 범위 밖

**코드는 건드리지 않았다.** 서비스·타입의 Go 전환은 별건이다.

## 추가 결정: Go 전용 구현과 역방향 갭 보고

2026-09-08 · 사용자 정책 변경에 따른 추가 기록. 초기 문서 배치 결정을 폐기하지 않는다.

1. **구현할 때는 `docs/api/go/`만 본다.** Laravel 문서는 기본적으로 열지 않는다.
2. **`docs/api/laravel/`은 역방향 참조 전용**이다. Go 계약만으로 구현이 불가능하거나 오류가 나는
   지점에만 열어, 과거 백엔드가 제공했던 응답·필드·엔드포인트와 Go의 부족한 계약을 근거로
   백엔드 요청 내용을 작성한다. 일반적인 이관 확인을 이유로 두 문서를 함께 읽지 않는다.
3. 갭은 [누적 대장](../api/backend-requests.md)에 고정 스키마로 기록한다. 대화나 코드 주석만으로
   끝내지 않는다. 현행 Go 계약, 요청안, 정적 불일치, 실행 재현 여부를 구분한다.
4. **Laravel은 구현 근거가 아니다.** Go 문서에 없으면 없는 계약으로 취급한다.
   과거 문서에서 타입·필드·기본값을 빌려 구현하지 않고 대장에 올린다.

### 기존 배치에 미치는 영향

- `docs/api/go/`·`docs/api/laravel/` 및 `docs/api/README.md`는 그대로 보존한다.
  스냅샷 속의 과거 읽기 안내보다 이 정책을 따른다. 본문 수정은 금지하고 대장만 예외로 신설한다.
- [API 카탈로그](../guides/api-catalog.md)는 Go 01~10 본문에서 확인한 **67개 고유 METHOD/경로**를
  주 표로 사용한다. Laravel 경로는 오른쪽 갭 보고용 열이다.
- 초기 기록의 `72 − 67 = 대응 없는 5개`는 대응 관계를 입증하는 방법이 아니다. 통합·신설 경로가
  있으므로 Go 본문으로 다시 대조했다. 기존 `✖ 없음` 5행은 별도 후보로 관리하고, Go 대체 계약이
  확인된 항목은 해결됨 또는 요청 불필요로 구분한다.
- [API 레퍼런스](../guides/api-reference.md)의 과거 경로·필드 예제는 Go 계약으로 갱신했다.
  코드 이관 여부는 호출·바인딩을 확인해 별도로 기록한다.
- 초기의 자동 삭제 시점은 이번 작업에서 실행하지 않는다. 역방향 요청 근거가 필요한 동안
  Laravel 스냅샷을 보존하며, 삭제는 별도 결정 사항이다.

### 프론트 Vue 규칙과의 경계

`jupiter-board-api`는 Laravel **백엔드**, `jupiter-board-web`은 Vue **프론트**다.
이번 변경은 백엔드 API 문서에만 적용한다. `CLAUDE.md` Screen work order 2번의
`../jupiter-board-web`을 동작 정본으로 먼저 읽는 절차와 읽기 권한 규칙은 그대로 유지한다.
`permissions-guide.md`의 Vue 분석 본문도 변경하지 않는다.

### 변경 범위와 확인

최초 검색은 `docs/api/**`를 제외한 `CLAUDE.md`·`.claude/**`·`docs/**`의 Markdown·shell·JSON에서
**8개 파일·78개 매칭 줄**, `.claude/hooks/*.sh`는 **0건**이었다.
추가 발견 파일은 `002-drive-canon-deviations.md`와 `features/post-detail/decision.md`다.
전자는 Vue UI 결정을 유지하면서 API 근거만 정정했고, 후자는 고정 공감 칩의 사용자 결정을
유지하면서 과거 API 문서가 구현 근거가 되던 설명을 제거했다.

`src/`는 읽기 전용으로 계약 불일치를 조사한다. 실제 연결된 화면이 Go 계약 적용 시 막히는
항목은 대장에 기록하되, 이미 Go 계약이 존재하는 프론트 미전환을 백엔드 누락으로 취급하지 않는다.
훅 파일·API 스냅샷·레거시 Vue 규칙은 이번 변경 대상이 아니다.

  이전 개수 차감·고정89 전제나 과거 줄번호는 현행 근거로 쓰지 않는다.

  Laravel 원문도 보존하며 실제 계약 갭의 역방향 요청 근거로만 사용한다.
- 코드 링크는 원문의 백엔드 상대경로를 그대로 보존한다. 복사본에서 코드 링크를 따라갈 때는
  [백엔드 원본 절대경로와 해석 안내](../api/README.md#source-links)를 사용한다.

  이번에 직접 수행한 검사로 보고하지 않으며, 프론트 코드의 Go 전환이나 실 API 호출 검증을 주장하지 않는다.
